# Dreamy Accessories — Stability & Admin UI Update

## Included changes
- Reworked `/admin/login` into a responsive premium pink/rose admin sign-in page.
- Added password show/hide eye control with accessible labels.
- Added clear handling for missing Supabase environment variables, invalid credentials, admin verification failures, and network/Failed to fetch errors.
- Admin login accepts either `NEXT_PUBLIC_SUPABASE_ANON_KEY` or `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (the URL remains `NEXT_PUBLIC_SUPABASE_URL`).
- Removed the Admin link from the public storefront footer. `/admin/login` remains a direct, unlinked URL.
- Added `noindex,nofollow,noarchive` metadata to admin routes.
- Centralized server-side API admin authorization and require an active `admin` or `super_admin` row for product, order, review, and analytics API routes.
- Kept service-role credentials server-only; no service-role key is included in this archive.

## Vercel deployment
Set these in Vercel → Project → Settings → Environment Variables for Production (and Preview/Development if used):

- `NEXT_PUBLIC_SUPABASE_URL` = `https://cfysxvozxwdqijdeomej.supabase.co`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` = your Supabase publishable key or legacy anon key

Alternative: set `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` instead of `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Do not set both to different projects.

After saving environment variables, redeploy the project. Next.js public environment variables are embedded at build time.

Do not add `SUPABASE_SERVICE_ROLE_KEY` unless a server-side feature actually needs it. Never prefix a service-role/secret key with `NEXT_PUBLIC_` and never paste it into client-side code.
